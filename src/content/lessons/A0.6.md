## Learning objectives

By the end of this lesson you will be able to:

1. **Distinguish** the two jobs of `static`: *internal linkage* at file scope (a name only this file can see) and *static storage duration* inside a function (a variable that keeps its value between calls). Say where each object lands (`.bss`, `.data`, `.rodata`, or the stack).
2. **Organize** a module so its header declares and its `.c` file defines: `extern` for shared objects, `static` for private ones, and no object defined in a header.
3. **Replace** function-like macros with `static inline` functions, `enum` and typed constants. Recognize the four classic macro bugs (precedence, double evaluation, multi-statement, no type) and write the rare macro that must stay a macro with `do { } while (0)`.
4. **Turn assumptions into build errors** with `static_assert`: configuration values, structure layouts, table sizes.
5. **Explain** why a static buffer makes a function non-reentrant, and fix it by passing the buffer in.
6. **Review** a small file against MISRA C:2012 (essential types, braces, `default`, return values, `stdio`), fix it, and write down the one justified deviation for a register address.

## Why this matters

A flight-data logger keeps a rolling peak of an ADC channel. One line does it:

```c
#define MAX(a, b)  ((a) > (b) ? (a) : (b))
...
peak = MAX(adc_read(), peak_limit);
```

It compiles without a warning and passes every bench test where the ADC is a constant. In the field the peak occasionally jumps to a value that was never above the limit when it was sampled. The macro pastes `adc_read()` into the expression **twice**: once to compare, once to take as the result. The ADC moved between the two reads. In the lab trace below, `MAX(adc_read(), 1000)` returns **2400** when the first sample was **1650**, and the converter was read twice.

Nothing in that macro is exotic. Embedded C hides this kind of trap in dozens of small places: a file-scope variable another file can reach by accident, a local buffer that is silently shared by every caller, a header that defines a variable and breaks the link, a configuration that is wrong on exactly one board. This lesson collects the habits that make those mistakes either impossible or loud. You'll use it directly in:
- The startup file and linker script: where `.data`, `.bss` and `.rodata` come from (A2.3, A2.4) and how to read a map file (A3.2)
- A clean GPIO driver API (A5.6) and ISR-shared data (A6.5)
- Ring buffers sized by `static_assert` (A8.4) and DMA buffers (A12.2)
- Defensive firmware design (A15.5)

## Concept explanation

````layer beginner
### `static` means two different things

The keyword `static` is one word with two unrelated jobs, and mixing them up is the most common source of confusion in embedded C.

```callout analogy title="Analogy: a private drawer and a notebook that stays on the desk"
**A `static` variable or function at file scope** is a *private drawer* in one office: nobody in the other offices can open it, even if they know its name. **A `static` variable inside a function** is a *notebook left on the desk*. A normal (automatic) local variable is a sticky note that's thrown away every time you leave the function. The notebook is still there when you come back, with what you wrote on it last time.
```

| Where | What `static` does | Example |
|---|---|---|
| **Outside** any function | The name is **private to this `.c` file** (internal linkage) | `static uint32_t s_counts[3];` |
| **Inside** a function | The variable **lives for the whole program** and remembers its value between calls (static storage) | `static uint32_t calls = 0U;` |
| **Neither** (no `static`) | A normal local variable: created at the call, gone at the return (automatic) | `uint32_t calls = 0U;` |

```anim
static-lifetime
```

In the lab, `count_calls_auto()` and `count_calls_static()` do the same `calls++` and return it. Three calls each give `1 1 1` and `1 2 3`.

### Why your files should hide things

If every variable and function can be reached from every file, any file can change any variable, and two files can accidentally use the same name. Marking everything that isn't part of a module's public interface `static` makes the compiler enforce that. The rest of the program *can't* depend on a variable you meant to keep private.

### Macros are find-and-replace

`#define SQUARE(x) x * x` is not a function. Before the compiler sees your code, a text tool pastes the macro's replacement over every `SQUARE(...)`. That has surprising results:

```anim
macro-expansion
```

`SQUARE(x + 1U)` becomes `x + 1U * x + 1U`. With `x = 3` that's 7, not 16. Macros have no types, no scope, and evaluate their arguments as many times as they are pasted. The fix, almost always, is a small `static inline` function, which behaves like a function (one evaluation, a real type) but costs no more than the macro.

### Let the compiler check your assumptions

Firmware is full of assumptions: "this buffer size is a power of two", "this struct is 8 bytes", "this baud rate fits the divider register". `static_assert(condition, "message")` checks the assumption **while compiling**. If it's false the build fails with your message, and the bad firmware never exists.

### Enums are named numbers

`typedef enum { EVENT_BUTTON, EVENT_TICK, EVENT_SELFTEST, EVENT_KIND_COUNT } EventKind;` gives the numbers names the debugger can show, lets the compiler warn about a `switch` that forgets a case, and keeps `EVENT_KIND_COUNT` in step with the list automatically.
````

````layer intermediate
### Storage duration and linkage

Every C object has a **storage duration** (how long it lives) and an identifier has a **linkage** (who can name it). The table is the whole story:

| Declaration | Linkage | Lifetime | Lands in | Costs |
|---|---|---|---|---|
| `uint32_t g_n;` (file scope) | **external**: any file can use it with `extern` | whole program | `.bss` | RAM |
| `static uint32_t s_n;` (file scope) | **internal**: this file only | whole program | `.bss` | RAM |
| `static uint32_t s_n = 5U;` | internal | whole program | `.data` | RAM, **plus** 4 bytes of Flash for the initial value (copied at boot, A2.3) |
| `const uint32_t k_n = 5U;` (file scope) | external (C) | whole program | `.rodata` | Flash only |
| `static const uint32_t k_n = 5U;` | internal | whole program | `.rodata` | Flash only |
| `uint32_t x;` inside a function | none | the call | stack (or a register) | stack |
| `static uint32_t x;` inside a function | none | whole program | `.bss` / `.data` | RAM |

The startup code (A2.3) zeroes `.bss` and copies `.data` from Flash. That's why a static or global **without** an initializer is `0` at boot, and why large initialized tables cost twice: once in Flash, once in RAM. The lab compiles the same 1 KB table three ways (`size/storage_classes.c`, arm-none-eabi-gcc 10.3 `-Os`, `arm-none-eabi-size`, verified):

| Table | `text` (Flash) | `data` (RAM + Flash image) | `bss` (RAM) |
|---|---|---|---|
| `static uint32_t t[256];` (no initializer, written elsewhere) | 32 | 0 | **1024** |
| `static uint32_t t[256] = {1,2,3};` (written elsewhere) | 32 | **1024** | 0 |
| `static const uint32_t t[256] = {1,2,3};` | **1040** | 0 | 0 |

The second row also needs a 1024-byte initial image in Flash: `size` counts it under `data`, not `text`, so the Flash cost of an initialized RAM table is `text + data`. The third row is Flash only: 1024 B in `text`, no RAM at all (A0.3).

### Declaration, definition, header

A **declaration** says a name exists; a **definition** creates the object. A program may define each object **exactly once** (the *one definition rule*, and for functions and objects with external linkage, the linker enforces it). The pattern for a module:

```c
/* event_counter.h : the contract */
extern const uint32_t g_eventCounterVersion;      /* declaration only */
void EventCounter_Record(EventKind kind);         /* function declaration */

/* event_counter.c : the implementation */
const uint32_t g_eventCounterVersion = 0x00010006UL;   /* the ONE definition */
static uint32_t s_counts[EVENT_KIND_COUNT];            /* private state */
```

```anim
linkage-map
```

Put a definition in a header and every file that includes it defines the object: the link fails. Real GCC 10.3 / GNU ld output for two files that both contain `int g_x = …;`: *`h2.o:(.data+0x0): multiple definition of 'g_x'; h1.o:(.data+0x0): first defined here`* (GCC 10 defaults to `-fno-common`, so even *uninitialized* duplicates are caught now; older toolchains merged them silently).

Header rules that keep a project sane:
- an **include guard** (`#ifndef FILE_H` … `#endif`) in every header;
- only **declarations, types, macros and `static inline` functions** in a header, never an object definition;
- a header includes what *it* needs (`<stdint.h>` for `uint32_t`) and nothing else, so it works on its own;
- name private state with a prefix (`s_` file-static, `g_` global, `k_` constant table) so a review can see the scope at a glance. Lab convention, not a language rule.

A `static` *function or table* in a header is legal, but each file that includes it gets its own copy. For `static inline` functions that's the point; for a data table it's a RAM or Flash waste.

### Macros, inline functions, enums and constants

The four classic macro bugs, each from `legacy_macros.h`, each compiling without a warning, each shown in the lab's bench with a real run:

| Bug | Macro | Expands to | Result |
|---|---|---|---|
| Parameter not parenthesised | `#define SQUARE(x) x * x` | `SQUARE(x + 1U)` → `x + 1U * x + 1U` | 7 instead of 16 (x = 3) |
| Whole expansion not parenthesised | `#define DOUBLE(x) (x) + (x)` | `10U * DOUBLE(x)` → `10U * (x) + (x)` | 33 instead of 60 |
| Argument evaluated twice | `#define MAX(a, b) ((a) > (b) ? (a) : (b))` | `MAX(i++, 3U)` → `((i++) > (3U) ? (i++) : (3U))` | `i` incremented twice; `MAX(adc_read(), 1000U)` reads the ADC twice |
| Several statements | `#define LED_PULSE() led_on(); led_off()` | `if (fault) LED_PULSE();` → `if (fault) led_on(); led_off();` | `led_off()` runs even when `fault` is false |

The replacements:

```c
static inline uint32_t square_u32(uint32_t x)          { return x * x; }
static inline uint32_t max_u32(uint32_t a, uint32_t b) { return (a > b) ? a : b; }
static inline void     led_pulse(void)                 { led_on(); led_off(); }
```

A `static inline` function evaluates each argument once, has typed parameters, obeys normal precedence, and at `-O1` and above compiles to the same instructions as the macro. For the rare macro that must stay one (it needs `__LINE__`, stringizing, or token pasting), wrap multiple statements in `do { … } while (0)`: it's a single statement that needs its trailing semicolon, so it behaves under an unbraced `if/else`:

```c
#define LED_PULSE_SAFE()   do { led_on(); led_off(); } while (0)
```

GCC ≥ 8 catches the unsafe version with `-Wmultistatement-macros` (part of `-Wall`): *"macro expands to multiple statements"* (verified, GCC 10.3). The lab's bench silences that one warning on one line, to be able to show the bug.

**Constants.** Choose by what you need:

| Form | Typed | Debugger sees it | Usable in an array size / `case` label | Costs |
|---|---|---|---|---|
| `#define N (16U)` | no (well, `unsigned int` by suffix) | no (preprocessed away) | yes | none |
| `enum { N = 16 };` | `int` | yes (as a name in the enum) | yes | none |
| `static const uint32_t N = 16U;` | `uint32_t` | yes (an object) | **no in C**: `static uint8_t buf[N];` at file scope gives *"error: variably modified 'buf' at file scope"* (verified, GCC 10.3) | may take Flash, usually optimized out |

The rule of thumb: `enum { … }` for integer constants and counts, `#define X (value)` with a suffix and parentheses for anything that must be `unsigned` or wider than `int`, `static const` for tables and values you want typed and addressable.

**Enums as types.** `typedef enum { … } EventKind;` plus a `switch (kind)` without `default:` makes GCC warn when you add a value and forget a case (`-Wswitch`). Add an `EVENT_KIND_COUNT` sentinel and size arrays with it, then `static_assert` the name table has the same length, as `event_counter.c` does.

### `static_assert`

C11's `_Static_assert(cond, "message")` and the `<assert.h>` macro `static_assert` (the lab uses the latter) require a constant expression and fail the build if it is false. Four uses worth making a habit:

```c
static_assert((LOG_BUFFER_SIZE & (LOG_BUFFER_SIZE - 1U)) == 0U, "must be a power of two (indices are masked)");
static_assert(USART_BRR_VALUE >= 16UL && USART_BRR_VALUE <= 0xFFFFUL, "USART_BRR out of range");
static_assert(sizeof(FrameHeader) == 8U, "FrameHeader must be 8 bytes on the wire");
static_assert((sizeof k_names / sizeof k_names[0]) == (size_t)EVENT_KIND_COUNT, "one name per EventKind");
```

Each is a check that otherwise lives in a comment, or in the head of the engineer who wrote it. Exercise 🟡 2 builds a full set for a UART logger and breaks it on purpose to see each message.

### Reentrancy: static buffers are shared state

```c
static const char *hex_static(uint32_t v)
{
    static char text[11];                  /* ONE buffer for every caller */
    snprintf(text, sizeof text, "0x%04lX", (unsigned long)v);
    return text;
}
Console_Printf("%s %s", hex_static(0xCAFEU), hex_static(0xBEEFU));   /* both pointers name the same buffer */
```

The two calls return the **same pointer**, so by the time `Console_Printf` runs, the buffer holds whichever call finished last, and the other value is lost. The same flaw bites across contexts: if `main()` and an ISR both call `hex_static()`, one overwrites the other mid-print (A6.5). The fix is to let the caller own the buffer: `hex_to(char *text, size_t size, uint32_t v)`. Standard-library functions with this flaw (`strtok`, `localtime`, `asctime`) have `_r` variants for the same reason.
````

````layer advanced
### Macro vs `static inline`: what the compiler really emits (GCC 10.3, `-Os`, verified)

From the lab's `size/inline_vs_macro.c`:

| C | Cortex-M4 code |
|---|---|
| `MAX(a, b)` and `max_u32(a, b)` with plain arguments | identical: `cmp r0, r1` · `it cc` · `movcc r0, r1` · `bx lr` |
| `peak_inline(limit)` = `max_u32(adc_read(), limit)` | `bl adc_read` · `cmp r0, r4` · `it cc` · `movcc r0, r4`: **one call** |
| `peak_macro(limit)` = `MAX(adc_read(), limit)` | `bl adc_read` · `cmp r0, r4` · `bls` over **a second `b.w adc_read`** (the second evaluation happens when the first sample won) |
| `crc8_4()`, a `static inline` helper called from four functions, at `-Os` | **not inlined**: one copy, each `frame_crc_x` is just `b.n crc8_4`; the whole object is **128 bytes** of text |
| The same with `__attribute__((always_inline))` | inlined four times: **210 bytes** of text |

Three consequences:
1. **Macro vs inline is not a speed question.** For simple helpers the output is identical, so choose on correctness. The macro's second `adc_read()` is the only difference above, and it is the bug.
2. **`inline` is a hint, not a command.** At `-Os` GCC kept the 8-iteration CRC helper out of line because inlining it four times costs 82 bytes more. Don't force `always_inline` for size; do it only for tiny helpers that must not call (such as code placed in RAM or an ISR trampoline), and measure with `arm-none-eabi-size`.
3. **Always `static inline` in headers, never plain `inline`.** C99/C11 `inline` without `static` or `extern` does not always emit an out-of-line definition, so an address-taken or unoptimized (`-O0`) call can fail at link time with *undefined reference*. `static inline` gives each file its own private copy and always links.

### Linkage details that matter at link time

- **`-fno-common`** (the default since GCC 10) turns two uninitialized definitions of one global into a link error. On older toolchains they were silently merged, which hid bugs such as two modules both defining `int g_flag;`.
- **`-ffunction-sections -fdata-sections -Wl,--gc-sections`** (the CubeIDE default) let the linker discard unreferenced functions and objects, but only if each has its own section. A `static` function that nothing calls is removed by the compiler before that. If something must stay (a vector, a boot marker), mark it `__attribute__((used))` and place it in a `KEEP()` linker-script section (A2.4).
- **`static` helps the optimizer.** A function the compiler knows can't be called from another file can be inlined at every call site and the out-of-line copy deleted, or have its calling convention changed. A non-static function must keep a conventional copy (unless link-time optimization is on).
- **Symbol names**: `static` objects get local ELF symbols, so two files can each have a `static int s_count;` and the map file lists both. A linker map (A3.2) shows `s_counts` under `.bss` with an address you can compare with the lab's `EventCounter_PrintStorage()`.
- **Function-local `static` objects** with a *constant* initializer are placed in `.data` or `.bss` and initialized by the startup code, exactly like file-scope ones. In C there is no run-time guard (C++ adds one for dynamic initialization), so there's no hidden cost.

### Enum size and `static_assert` on layouts

`arm-none-eabi-gcc` uses `-fshort-enums` by default: `enum { A, B }` is **1 byte** (verified), while the PC compiler uses 4. The lab prints `sizeof(EventKind)`: expect 4 on the PC and 1 on the board (see the console block). Never put an enum in a wire format or a Flash record; use a fixed-width integer and `static_assert` that every enumerator fits it. A prebuilt library compiled without `-fshort-enums` has a different layout for any struct containing an enum than your code: the Arm linker reports an enum-size attribute mismatch between the objects, so watch for that warning when linking a vendor library.

### What MISRA C is, and what it is not

**MISRA C:2012** (with its Amendments) is a set of coding guidelines for C in safety-related systems: 143 *rules* and 16 *directives*, each *Mandatory*, *Required* or *Advisory*. Rules are decidable from the source alone (a tool can prove a violation); directives need judgment (documentation, design). It is **not** a language, a compiler setting or a safety certificate. It reduces the chance of the bugs in this lesson, and compliance is shown by tool output plus a list of documented **deviations**.

Rules from this lesson that appear in almost every first review:

| Rule | Says | Where in this lesson |
|---|---|---|
| Dir 4.9 (advisory) | Prefer a function to a function-like macro | `SQUARE`, `MAX` |
| 20.7 (required) | Macro parameters are parenthesised | `SCALE(x) x * 10` |
| 8.4 (required) | An external object or function has a visible declaration | `g_mode`, `process()`, `led_set()` with no header |
| 8.7 (advisory) | Externally visible only if needed | `g_mode` is used in one file: make it `static` |
| 10.1, 10.4 (required) | No operations on inappropriate essential types; both operands of arithmetic share an essential type category | `offset + sample` (signed + unsigned), `result >> 1` on a signed value |
| 15.6 (required) | The body of every `if`/loop is a compound statement | `if (total > 100) total = 100;` |
| 16.4 (required) | Every `switch` has a `default` | `switch (g_mode)` |
| 14.4 (required) | A controlling expression is essentially Boolean | `if (g_mode)` |
| 17.7 (required) | A function's return value is used (or cast to `void`) | `clamp_add(0, sample);` |
| 21.6 (required) | No `<stdio.h>` | `printf` in the file |
| 11.4 (advisory) | No conversion between a pointer and an integer | `(volatile uint32_t *)0x40020014UL` |
| 15.5 (advisory) | A single exit point | `return;` in the middle of `led_set()` |

Rule numbers and wording are quoted from the 2012 edition as I read it; the standard is sold, so check them against your own copy and against your tool's rule text. The lab's `misra/misra_demo.c` has these violations on purpose. **No MISRA checker was run for this lesson**: the list above is from reading the code against the rules. Tools to run it with are Cppcheck Premium or its open-source `misra` addon, PC-lint, Polyspace, Helix QAC and Coverity. They differ in which rules they can decide.
````

## Common mistakes & debugging

### 1. A global defined in a header
- **Symptom:** *`multiple definition of 'g_x'; … first defined here`* at link time (GCC ≥ 10), or silent duplicates on older toolchains.
- **Why:** each `.c` that includes the header creates its own definition.
- **Fix:** `extern` declaration in the header, one definition in one `.c` file. Or make it `static` (and accept one copy per file).

### 2. A variable that was meant to be private is global
- **Symptom:** another module changes your state; two files both define `counter` and corrupt each other (or fail to link).
- **Why:** no `static`, so the name has external linkage.
- **Diagnose:** `arm-none-eabi-nm --defined-only app.elf | grep -i " [BbDd] "`: uppercase letters are global symbols, lowercase are local.
- **Fix:** `static` on everything not in the header. Prefix private state `s_`.

### 3. `static` where you meant an ordinary local
- **Symptom:** a function returns different results on identical calls; a "reentrant" helper isn't; the result depends on the previous caller.
- **Why:** a function-local `static` holds state between calls and is shared by every caller, including an ISR.
- **Fix:** use `static` locals only for deliberate state (an edge detector, a counter). Pass buffers in (`hex_to(buf, size, v)`).

### 4. Returning a pointer to a local array
- **Symptom:** garbage in the result after the function returns; it works until another call reuses that stack.
- **Why:** an automatic array dies at the return. `static` would keep it alive but shared (mistake 3).
- **Fix:** the caller supplies the buffer and its size.

### 5. A macro argument with a side effect
- **Symptom:** a value skips, a read happens twice, a counter increments by two (`MAX(i++, 3U)` leaves `i` two higher).
- **Why:** the macro pastes the argument as many times as the parameter appears.
- **Fix:** `static inline` function. If it must be a macro, never pass side effects, and document it in the name (`MAX_NOSIDEEFFECTS`) or the comment.

### 6. Missing parentheses in a macro
- **Symptom:** `SQUARE(x + 1U)` is 7, `10U * DOUBLE(x)` is 33 (with `x = 3`): wrong at every optimization level, but only for some arguments, so tests with a plain variable pass.
- **Why:** textual substitution ignores precedence.
- **Fix:** parenthesise every parameter and the whole expansion: `((x) * (x))`. Better: a function.

### 7. A multi-statement macro under an `if`
- **Symptom:** the second statement always runs. GCC says *"macro expands to multiple statements"* (verified). Without that warning, nothing says anything.
- **Fix:** `do { … } while (0)`, or a function.

### 8. Configuration that is wrong on one board only
- **Symptom:** a ring buffer with `idx & (SIZE - 1)` loses data when someone sets `SIZE` to 100; the baud rate is 2 % off on a board with a different clock.
- **Fix:** `static_assert` the power of two, the divider range, and the clock/baud relationship (Exercise 🟡 2).

### 9. Trusting `sizeof` of a struct or enum across compilers
- **Symptom:** a struct is 8 bytes in the host test, 5 on the board; an enum field changes the layout of a shared header.
- **Why:** padding, bit-fields and enum width are ABI-dependent (A0.5).
- **Fix:** `static_assert(sizeof(T) == N)` in the **target** build; fixed-width members in anything shared.

### 10. `switch` over an enum without `default`, then a value is added
- **Symptom:** a new `EventKind` is silently ignored in one `switch`.
- **Fix:** `-Wswitch` (in `-Wall`) catches the *no-default* form; MISRA wants a `default:` anyway (16.4). Use both: a `default:` that handles the "impossible" value, plus `-Wswitch-enum` on code you want warned on every missing enumerator.

## Best practices & production tips

```callout production title="Hygiene habits of a firmware codebase that stays healthy"
- **Everything private is `static`.** Header = contract: types, prototypes, `extern` declarations and `static inline` helpers only. One definition of each object, in one `.c` file.
- **Name the scope.** `g_` for globals, `s_` for file statics, `k_` for constant tables. A reviewer can see at a glance what an ISR can touch.
- **No function-like macros for logic.** `static inline` functions and `enum` constants. Keep macros for `#include` guards, token pasting, stringizing, and `__FILE__`/`__LINE__`.
- **Macros that remain:** parenthesise every parameter and the whole expansion, `do { } while (0)` for statements, and never pass side effects.
- **No `static` buffers in functions anyone else calls.** The caller owns the buffer and passes its size (the `snprintf` pattern).
- **`static_assert` is documentation that can't go stale:** clock/baud arithmetic, power-of-two sizes, struct and enum layouts, table lengths, `sizeof(T) <= MAX`. Put them next to the definition they protect.
- **Enums for states and kinds, with a `_COUNT` sentinel**, `default:` in every `switch`, and range-check enums coming from outside.
- **Compile with the full warning set from day one:** `-Wall -Wextra -Wconversion -Wsign-conversion -Wshadow -Wswitch-enum`, and treat warnings as errors in CI (`-Werror`). It is far cheaper than adding it to 50,000 lines later.
- **Adopt MISRA C incrementally:** start with the high-yield rules (braces, `default`, return values, essential types, no `stdio`), run a checker in CI, and write every deviation down (rule, reason, scope, approver).
- **Keep deviations small and isolated.** Register access (Rule 11.4) lives in one header or one module, with the deviation recorded once.
```

## Cheat sheet

```callout tip title="A0.6 on one screen"
**`static`:** file scope → private to the file (internal linkage). Inside a function → one object for the whole program, keeps its value between calls (not reentrant). Automatic local → new at every call.

| Declaration | Lands in | Costs |
|---|---|---|
| global / `static`, no initializer | `.bss` | RAM, zeroed by startup |
| global / `static`, initialized | `.data` | RAM **and** Flash image |
| `const` / `static const` table | `.rodata` | Flash only |
| automatic local | stack / register | stack |

**Header = contract:** guard · types · prototypes · `extern` declarations · `static inline`. **One definition** per object, in a `.c` file. `-fno-common` (GCC ≥ 10): duplicate globals fail to link.

**Macros → functions:** `SQUARE(x+1)` → `x+1*x+1` · `MAX(f(),b)` evaluates `f()` twice · `A(); B()` under an `if`. Use `static inline`; if you must, `((x) * (x))` and `do { … } while (0)`.

**Constants:** `enum { N = 16 };` (usable in array sizes) · `#define N (16U)` · `static const` (not a C constant expression).

**`static_assert(cond, "msg")`:** power-of-two sizes · divider ranges · `sizeof`/`offsetof` of layouts · name-table length == enum count.

**Enums:** `-fshort-enums` on arm-none-eabi (1 byte vs 4 on PC) · `_COUNT` sentinel · `default:` in every `switch`.

**Reentrancy:** no `static` buffers in shared functions; the caller passes `buf, size`.

**MISRA first pass:** braces (15.6) · `default` (16.4) · Boolean conditions (14.4) · essential types (10.1/10.4) · use or `(void)` return values (17.7) · no `stdio` (21.6) · parenthesised macros (20.7) · declare externals (8.4) · register cast = documented deviation (11.4).
```

- **GCC manual**: *An Inline Function is As Fast As a Macro*; *Inline* (C99 and GNU inline semantics); *Warning Options* → `-Wmultistatement-macros`, `-Wswitch`, `-Wswitch-enum`; *Code Gen Options* → `-fno-common`, `-fshort-enums`; *Common Function Attributes* → `always_inline`, `used`.
- **MISRA C:2012 (with Amendments 1 to 4)**: Directive 4.9; Rules 8.4, 8.7, 10.1, 10.4, 11.4, 14.4, 15.5, 15.6, 16.4, 17.7, 20.7, 21.6, and the guidance on deviations (*MISRA Compliance:2020*). The documents are sold by MISRA; a Cppcheck-based open-source addon covers many of the decidable rules.
- **Arm AAPCS32 (IHI 0042)**: *Enumeration types* (why `-fshort-enums` is the default for arm-none-eabi).
- **STM32CubeIDE** *Build settings*: `-ffunction-sections -fdata-sections` and `--gc-sections` (Properties → C/C++ Build → Settings).
