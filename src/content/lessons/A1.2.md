## Learning objectives

By the end of this lesson you will be able to:

1. **Name** every core register (R0–R12, SP with its two banks MSP and PSP, LR, PC, xPSR) and say who may use it, using the AAPCS roles (arguments, scratch, callee-saved).
2. **Recognize** the AAPCS in compiled code: where arguments arrive, where results leave, and why a function that needs R4–R8 starts with a `push` and ends with a `pop`.
3. **Decode** xPSR into its flags (N, Z, C, V, Q), the Thumb bit, the IT bits and the exception number, and **compute** the flags of `ADDS` and `SUBS` by hand, including the rule that *C after a subtraction means "no borrow"*.
4. **Choose** the right condition code for a comparison: `HS`/`LO`/`HI`/`LS` for unsigned values, `GE`/`LT`/`GT`/`LE` for signed ones, and say which flags each reads.
5. **Predict** which interrupt priorities run for any combination of PRIMASK, FAULTMASK and BASEPRI on a part with 4 priority bits (levels, priority bytes, the "numerically greater or equal is blocked" rule).
6. **Write** a nestable critical section that saves and restores the mask instead of blindly re-enabling interrupts, and read the CONTROL register to tell privilege and stack choice.

## Why this matters

An embedded team protects a shared ring buffer with the usual pair:

```c
void Buffer_Push(uint8_t byte)
{
    __disable_irq();
    ring[head++ & MASK] = byte;
    __enable_irq();
}
```

It works for months. Then a colleague calls `Buffer_Push()` from inside a longer section that already runs with interrupts off, to keep two updates consistent:

```c
__disable_irq();
update_header();
Buffer_Push(b);        /* ends with __enable_irq() ... */
update_footer();       /* ... which now runs with interrupts ON */
__enable_irq();
```

The inner `__enable_irq()` ends the *outer* critical section early. A UART interrupt can now land between `Buffer_Push()` and `update_footer()` and corrupt the frame, once a day, never on the bench. The fix is one line: remember what the mask was (`__get_PRIMASK()`), and put exactly that back. To see why, you need to know that PRIMASK is a register with a value, not a switch, and what the other mask registers do.

Everything the CPU does passes through the registers of this lesson: the arguments of your functions, the flags behind every `if`, the stack pointer an RTOS swaps on every task switch, the mask that decides whether an interrupt may run. You'll use it directly in:
- Privilege levels and the two stack pointers (A1.3), and the FPU registers (A1.6)
- The vector table: the first word is the initial SP, the second the initial PC (A2.2)
- NVIC priorities, `BASEPRI` and what FreeRTOS does with it (A6.2, B1.2)
- Exception entry and exit, the stacked registers and `EXC_RETURN` (A6.4), ISR-shared data (A6.5)
- Reading a fault: the stacked PC, LR and xPSR (A15.2)

## Concept explanation

````layer beginner
### The CPU's workbench: sixteen drawers

The processor can only work on data that is in its **registers**: a few very fast 32-bit storage slots inside the core. To add two variables it loads them from memory into registers, adds, and stores the result. There are sixteen general registers, named `R0` to `R15`, and a few special ones.

```callout analogy title="Analogy: a workbench with sixteen drawers and a few instruments"
Memory is the warehouse across the street: huge but slow. The registers are sixteen drawers on the workbench: only what's in a drawer can be worked on, and there are very few of them, so the compiler is constantly deciding what stays in a drawer. Three of the drawers have fixed jobs (the **stack pointer** says where the day's scratch pad starts, the **link register** remembers where to go back to after a call, the **program counter** points at the next instruction). Next to the bench hang a few instruments: a **status panel** with lights for "result was zero", "result was negative", "overflow" (the flags), and a **door lock** that decides whether the phone (an interrupt) may ring while you work.
```

The animation walks through them:

```anim
register-file
```

What you need to remember:
- **R0–R12**: general purpose. The compiler uses them for your variables and for passing arguments.
- **SP (R13)**: the stack pointer. Every function call and every interrupt uses the stack.
- **LR (R14)**: where to return after a function call.
- **PC (R15)**: the address of the next instruction. Changing it is a jump.
- **xPSR**: the *status* register. It holds the flags that `if` and `while` are built on, and the number of the interrupt currently running.
- **PRIMASK, BASEPRI, FAULTMASK**: whether interrupts are allowed (next sections).
- **CONTROL**: whether the program runs privileged, and which stack it uses (A1.3).

### The flags are what `if` is made of

Every comparison compiles to two steps: an instruction sets the **flags** (`CMP r0, r1` computes `r0 − r1` and throws the result away, keeping only the flags), then a conditional branch reads them (`BEQ`, `BNE`, `BLT`, `BHS`, …). The four flags are **N** (the result was negative), **Z** (it was zero), **C** (carry) and **V** (signed overflow). The lab prints a table of them for chosen additions and subtractions.

### Interrupts can be switched off

Sometimes code must not be interrupted: two variables must change together, or a counter shared with an ISR is being updated. The core has a *mask* register for that: set it, and interrupts wait; clear it, and they run. The catch, as in the story above, is to put the mask back the way you found it.
````

````layer intermediate
### The registers and their jobs

| Register | Width | Job | Notes |
|---|---|---|---|
| R0–R3 | 32 | arguments and return value, **scratch** | A called function may overwrite them |
| R4–R11 | 32 | **callee-saved** | A function that uses them must restore them |
| R12 (IP) | 32 | scratch | Linker veneers may use it |
| R13 (SP) | 32 | stack pointer | Two banks: **MSP** and **PSP**; AAPCS wants 8-byte alignment at calls |
| R14 (LR) | 32 | link register | Return address, or `EXC_RETURN` inside a handler |
| R15 (PC) | 32 | program counter | Bit 0 reads as 0; a branch target needs bit 0 = 1 (Thumb) |
| xPSR | 32 | APSR + IPSR + EPSR | Flags, exception number, Thumb and IT state |
| PRIMASK | 1 | blocks all configurable exceptions | Reset value 0 |
| FAULTMASK | 1 | blocks everything except NMI | Reset value 0; cleared on exception return (not NMI) |
| BASEPRI | 8 (top 4 used on the F446) | blocks priorities ≥ its value | 0 = off |
| CONTROL | 3 | nPRIV, SPSEL, FPCA | Thread-mode privilege and stack |

**R0–R7** can be used by every instruction, including the 16-bit Thumb ones; **R8–R12** by most 32-bit ones. That is why compiled code prefers R0–R7.

### The calling standard (AAPCS) in compiled code

Arm's procedure call standard says who may destroy which register. The lab's `size/aapcs.c` shows each rule in the machine code, compiled with arm-none-eabi-gcc 10.3 `-O2` for the F446 (verified):

| C | Code | What it shows |
|---|---|---|
| `sum5(a, b, c, d, e)` | `push {r4}` · `ldr r4, [sp, #4]` · `add r3, r4` · … · `add r0, r3` · `ldr.w r4, [sp], #4` | The first four arguments are in R0–R3; the **fifth is on the stack**. The result is in R0. The function used R4, so it saved and restored it |
| `widen_mul(a, b)` (returns `uint64_t`) | `umull r0, r1, r0, r1` · `bx lr` | A 64-bit result comes back in **R1:R0** |
| `half(float x)` | `vmov.f32 s15, #0.5` · `vmul.f32 s0, s0, s15` | With the hard-float ABI a float argument and result live in **S0** |
| `keeps_across_call(a, b, c)` | `stmdb sp!, {r4, r5, r6, r7, r8, lr}` … `ldmia.w sp!, {r4, r5, r6, r7, r8, pc}` | Values that must survive a call go in R4–R8, so the function **saves them, and LR, first**, and returns by popping straight into **PC** |
| `leaf(a, b)` | `add.w r0, r1, r0, lsl #3` · `bx lr` | A function that needs no saved register has no push or pop at all |

This is also what an interrupt handler's frame exists for: when an exception interrupts running code, the hardware must save the *caller-saved* registers (R0–R3, R12, LR, PC, xPSR) for it, because the code that was interrupted never expected a call (A6.4).

### xPSR: three views of one register

| Bits | Name | Meaning |
|---|---|---|
| 31 | **N** | negative: bit 31 of the result |
| 30 | **Z** | zero |
| 29 | **C** | carry (add) / **not borrow** (subtract, compare) |
| 28 | **V** | signed overflow |
| 27 | **Q** | sticky saturation flag, set by DSP instructions |
| [26:25], [15:10] | IT / ICI | state of an `IT` block, or of an interrupted multi-register load/store |
| 24 | **T** | Thumb state: always 1 on a Cortex-M |
| [19:16] | GE | SIMD "greater or equal" flags (M4/M7) |
| [8:0] | **ISR number** | 0 in thread mode, else the number of the running exception |

APSR is the flags and GE, IPSR is the exception number, EPSR is T and the IT bits. `MRS r0, xPSR` reads them together (CMSIS: `__get_xPSR()`; the compiler emits `mrs r0, PSR`). Reading the EPSR part through MRS returns zeros (DUI 0553), so the Thumb bit isn't visible this way; the copy of xPSR that exception entry pushes on the stack does have T = 1.

The exception numbers (IPSR):

| IPSR | Exception | IPSR | Exception |
|---|---|---|---|
| 0 | Thread mode (no exception) | 11 | SVCall |
| 2 | NMI | 12 | Debug monitor |
| 3 | HardFault | 14 | PendSV |
| 4 | MemManage | 15 | SysTick |
| 5 | BusFault | 16 + *n* | external interrupt *n* (IRQ*n*) |
| 6 | UsageFault | | |

So inside the EXTI0 handler (IRQ 6) IPSR is **22**, and inside `SysTick_Handler` it is **15**: the lab prints both.

### Computing the flags

Addition and subtraction set all four flags from the 32-bit result:

| Flag | After `ADDS a, b` | After `SUBS a, b` / `CMP a, b` |
|---|---|---|
| N | bit 31 of the result | bit 31 of the result |
| Z | result == 0 | result == 0 |
| C | unsigned carry out: `result < a` | **no borrow**: `a >= b` (unsigned) |
| V | `a` and `b` have the same sign, the result a different one | `a` and `b` have different signs, the result's sign differs from `a` |

The surprise is the subtract C: ARM defines it as `NOT borrow`, so after `CMP 5, 5` or `CMP 7, 3` the carry flag is **set**, and after `CMP 3, 5` it is **clear**. The lab's `Flags_Add()` and `Flags_Sub()` implement this and are cross-checked against the compiler's own overflow built-ins on 100,000 operand pairs (0 mismatches).

### Condition codes: pick by signedness

| Code | Meaning | Flags tested | Use for |
|---|---|---|---|
| `EQ` / `NE` | equal / not equal | Z | any |
| `HS` (`CS`) | unsigned `>=` | C = 1 | **unsigned** |
| `LO` (`CC`) | unsigned `<` | C = 0 | unsigned |
| `HI` | unsigned `>` | C = 1 and Z = 0 | unsigned |
| `LS` | unsigned `<=` | C = 0 or Z = 1 | unsigned |
| `GE` | signed `>=` | N = V | **signed** |
| `LT` | signed `<` | N ≠ V | signed |
| `GT` | signed `>` | Z = 0 and N = V | signed |
| `LE` | signed `<=` | Z = 1 or N ≠ V | signed |

The compiler picks the family from the **types** in your C. That is the machine-level reason for the signed/unsigned comparison trap of A0.1: `0x80000000 < 1` is true for `int32_t` (`LT`: N = 0, V = 1, so N ≠ V) and false for `uint32_t` (`LO`: C = 1).

### PRIMASK, FAULTMASK, BASEPRI

All exceptions have a **priority**: a number, where *lower means more urgent*. Reset, NMI and HardFault have fixed negative priorities (−3, −2, −1); everything else is configurable. The mask registers raise the *current execution priority*:

| Register | Effect | Blocks |
|---|---|---|
| **PRIMASK** = 1 | priority raised to 0 | every configurable exception (priority ≥ 0). NMI and HardFault still run |
| **FAULTMASK** = 1 | priority raised to −1 | everything except NMI, including HardFault. Clears itself when an exception returns |
| **BASEPRI** = *b* (non-zero) | priority raised to *b* | every exception whose priority number is ≥ *b*; more urgent ones still run |

The priority is stored left-aligned in 8 bits, and the F446 implements only the top 4 (`__NVIC_PRIO_BITS = 4`, A1.1). So a priority **level** *n* (0 to 15) is the byte `n << 4`, and BASEPRI ignores its low 4 bits: writing `0x55` reads back `0x50`. BASEPRI = `0x50` means "block levels 5 to 15, let levels 0 to 4 run". Click through the combinations:

```anim

```

BASEPRI is the more civilized tool: it protects a critical section from *some* interrupts and leaves the most urgent ones running. FreeRTOS on the Cortex-M4 does exactly this: its critical sections set BASEPRI to `configMAX_SYSCALL_INTERRUPT_PRIORITY`, so interrupts above that level (never calling the kernel) are never delayed (B1.2).

### Writing the registers: MRS, MSR, CPS

| C (CMSIS) | Instruction (verified, GCC 10.3) |
|---|---|
| `__disable_irq()` | `cpsid i` (sets PRIMASK) |
| `__enable_irq()` | `cpsie i` (clears PRIMASK) |
| `__get_PRIMASK()` | `mrs r0, PRIMASK` |
| `__set_BASEPRI(x)` | `msr BASEPRI, r0` |
| `__set_BASEPRI_MAX(x)` | `msr BASEPRI_MAX, r0` (writes only if `x` is more restrictive) |
| `__disable_fault_irq()` | `cpsid f` (sets FAULTMASK) |
| `__get_xPSR()` | `mrs r0, PSR` |
| `__set_CONTROL(x)` | `msr CONTROL, r0` **followed by `isb`** (CMSIS adds it) |
| `__get_MSP()` | `mrs r0, MSP` |

Unprivileged code can't write the special registers (the writes are ignored): see A1.3.

### The nestable critical section

Because PRIMASK is a *value*, the correct pattern **saves it, disables, and restores the saved value**:

```c
uint32_t saved = __get_PRIMASK();
__disable_irq();
/* ... critical work ... */
__set_PRIMASK(saved);          /* NOT __enable_irq() */
```

If the section was entered with interrupts already off, `saved` is 1 and the restore keeps them off. The nesting can go as deep as it likes. Exercise 🟡 2 builds it on a model.
````

````layer advanced
### What an exception does to these registers

When an exception is taken, the hardware does the work of a function call for you, in this order (A6.4 has the details):

1. Pushes **eight words** onto the current stack: R0, R1, R2, R3, R12, LR, PC and xPSR (the stacked PC is the address the interrupted code returns to; this is what you read in a fault handler). With an active FPU context the frame is 26 words (S0–S15, FPSCR and a reserved word are added, A1.6).
2. Writes `EXC_RETURN` into **LR**.
3. Sets IPSR to the exception number and switches to Handler mode on the **MSP**.
4. Loads **PC** from the vector table.

If the stack pointer isn't 8-byte aligned when the exception arrives, and `CCR.STKALIGN` is set (the reset value on the Cortex-M4), the hardware inserts one padding word and records it in bit 9 of the *stacked* xPSR, so the return can undo it. This is why the stack pointer inside a handler isn't always the old SP minus 32.

Callee-saved R4–R11 are **not** pushed by the hardware, because a normal function would preserve them anyway. The RTOS context switch (B1.2) saves them itself, and that is the part of the switch written in assembly.

### Execution priority, and what "masked" really means

The core keeps a *current execution priority*: the priority of the exception being handled, or, in thread mode, the base level. PRIMASK, FAULTMASK and BASEPRI *raise* that level for thread-mode code. An exception preempts only if its priority is **strictly more urgent** (numerically lower) than the current level. So:
- `BASEPRI = 0x50` blocks priority bytes `0x50` and above (levels 5 to 15) and lets `0x40` and below run (levels 0 to 4). The lab verifies this on the real NVIC at levels 4, 5 and 9.
- A **masked** interrupt is not lost: it stays *pending*. When the mask is removed it runs. The lab's table shows `ran while masked: no`, `ran after unmask: yes`. (Only a second occurrence of the same interrupt while it was pending would be merged with the first: the NVIC pends once per line.)
- **FAULTMASK** exists so a fault handler can run code that is not interrupted by another fault, and so that the `BFHFNMIGN` probe of A0.4 works. It is cleared automatically on exception return (except from NMI).
- The effect of `msr BASEPRI` isn't guaranteed to be visible to the very next instruction without barriers: the CMSIS-based RTOS ports follow it with `dsb` and `isb`, and so should your code when an interrupt that has just been made pending must not be taken.

### Why BASEPRI_MAX exists

Plain `msr BASEPRI, x` *replaces* the mask. In a nested critical section that is wrong: if an outer section blocked from level 2 (`0x20`) and an inner one writes `0x80`, the inner write **lowers** the protection to level 8 and above, and when it later writes 0 on exit, the outer section is unprotected altogether. `msr BASEPRI_MAX, x` writes only when it makes the mask *more* restrictive (`x` non-zero and lower than the current BASEPRI, or BASEPRI is 0), and the section restores the saved value on exit. The model in Exercise 🔴 3 shows both versions side by side). FreeRTOS's ARM_CM4F port solves the same problem differently: it uses a plain `msr basepri` followed by `isb` and `dsb`, a nesting counter (`uxCriticalNesting`) for task-level sections, and `ulPortRaiseBASEPRI()`, which returns the original BASEPRI so the ISR-level macros can restore it. The `_MAX` form is the instruction-level guarantee that a write can only raise the mask.

### PC, LR and the Thumb bit in disassembly

A function return `bx lr` or `pop {…, pc}` needs the target's bit 0 set. For a normal call (`bl`) the hardware writes `LR = next instruction | 1`, so the return works. In the vector table the same rule applies: every handler address is stored with bit 0 set (the linker does it for Thumb functions), and a handler address with bit 0 clear faults with `INVSTATE` the moment it is taken (A2.2). Reading R15 in an instruction gives the instruction's address plus 4 (the pipeline), with bit 0 clear.

### CONTROL, in more detail

| Bit | Name | 0 | 1 |
|---|---|---|---|
| 0 | nPRIV | thread mode privileged | thread mode **unprivileged** |
| 1 | SPSEL | thread mode uses MSP | thread mode uses **PSP** (ignored in Handler mode, which always uses MSP) |
| 2 | FPCA | no floating-point context | FP context active (set by hardware at the first FP instruction; A1.6) |

`__set_CONTROL()` must be followed by an `ISB` so the new stack or privilege takes effect before the next instruction, which is why CMSIS's version contains one (verified). Only privileged code can write CONTROL. Handler mode is always privileged and always on the MSP.

### Registers the F4 adds

With the FPU: S0–S31 (32 single-precision registers, also seen as D0–D15) and FPSCR (flags and rounding mode), enabled by `CPACR`. They have their own AAPCS roles: S0–S15 are scratch, S16–S31 callee-saved. They are the subject of A1.6.
````

## Under the hood

### Register map

| Item | Access | Reset | Reached by |
|---|---|---|---|
| R0–R12 | rw | unknown | any instruction |
| MSP (R13) | rw | word 0 of the vector table | `MRS`/`MSR MSP`, or as SP |
| PSP (R13) | rw | unknown | `MRS`/`MSR PSP` |
| LR (R14) | rw | `0xFFFFFFFF` | any instruction |
| PC (R15) | rw | word 1 of the vector table (bit 0 ignored) | branches, `pop {pc}` |
| xPSR | APSR rw, IPSR r, EPSR r | `0x01000000` | `MRS xPSR` / `MSR APSR_nzcvq` |
| PRIMASK, FAULTMASK, BASEPRI, CONTROL | rw, privileged | 0 | `MRS`/`MSR`, `CPSID`/`CPSIE` |

The lab's `Xpsr_Decode()` implements exactly the xPSR layout above and is tested against built values.

### Line-by-line: the non-obvious lines

| Line | Explanation |
|---|---|
| `const uint32_t result = a + b;` (`Flags_Add`) | Unsigned arithmetic wraps modulo 2³², which is defined. A signed addition that overflows would be undefined behavior (A0.1), so the model never uses one. |
| `f.c = (result < a);` | If the sum wrapped, it is smaller than an operand: that's the unsigned carry out. |
| `(((a ^ result) & (b ^ result) & SIGN_BIT) != 0U)` | Signed overflow of an addition: both operands have the sign that the result *lacks*. |
| `f.c = (a >= b);` (`Flags_Sub`) | ARM's carry after a subtraction is *no borrow*: set when `a >= b` unsigned. |
| `(((a ^ b) & (a ^ result) & SIGN_BIT) != 0U)` | Overflow of a subtraction: the operands have different signs, and the result's sign differs from `a`'s. |
| `out->it = (xpsr >> 25 & 3) \| ((xpsr >> 10 & 0x3F) << 2)` | The IT/ICI state is split in two places in the register and must be reassembled. |
| `Priority_Encode(level, bits)` = `level << (8 - bits)` | Priorities are left-aligned: with 4 bits implemented, level 5 is the byte `0x50`. |
| `Basepri_ReadBack(value, bits)` | The unimplemented low bits of BASEPRI read as 0: `0x55` acts as `0x50`. |
| `return (basepri != 0U) && (priorityByte >= basepri);` | BASEPRI = 0 means *off*. Otherwise the more urgent (numerically lower) priorities pass. |
| `NVIC_SetPriority(LAB_IRQ, level)` | CMSIS shifts the level into the implemented top bits for you. |
| `NVIC_SetPendingIRQ(LAB_IRQ); __DSB(); __ISB();` | Sets the interrupt pending in software (the EXTI is not involved) and makes sure the pend and any resulting exception are processed before the next C statement. |
| `out->ranWhileMasked = (s_handlerRuns != before);` | `s_handlerRuns` is `volatile` (A0.3); without it the compiler could assume the handler never runs. |
| `s_handlerIpsr = __get_IPSR();` | Reads the exception number from inside the handler: 22 for IRQ 6. |
| `__set_BASEPRI(0U)` at the end | Removes the mask. After the barriers, a pending interrupt that was masked runs. |
| `void HAL_IncTick(void) { uwTick += uwTickFreq; … }` (`main.c`) | Our version of the HAL's weak function: same effect, plus the IPSR capture. |

## Common mistakes & debugging

### 1. `__enable_irq()` at the end of a critical section
- **Symptom:** rare data corruption; an interrupt runs inside an outer critical section.
- **Why:** the exit unconditionally clears PRIMASK, ending the outer section as well.
- **Diagnose:** `__get_PRIMASK()` at the end of the inner function: it's 0 where it should be 1.
- **Fix:** `saved = __get_PRIMASK(); __disable_irq(); … __set_PRIMASK(saved);`.

### 2. Plain `BASEPRI` write in a nested section
- **Symptom:** a high-priority section loses its protection after a lower-priority function returns.
- **Why:** `msr BASEPRI, x` can *lower* the mask, and an exit that writes 0 clears all of it (verified in the model: `0x20` becomes `0x80`, then `0x00`).
- **Fix:** `__set_BASEPRI_MAX(x)` on entry and restore the saved value on exit.

### 3. Comparing priority levels the wrong way round
- **Symptom:** an interrupt meant to be "above" the RTOS is blocked by its critical sections.
- **Why:** a *lower* number is *more* urgent. `BASEPRI = 0x50` blocks `0x50` and *higher numbers*.
- **Fix:** draw the 16 levels (this lesson's widget), mark which must be served during critical sections, and set the threshold accordingly (A6.2).

### 4. Writing a priority level where a priority byte is expected
- **Symptom:** `__set_BASEPRI(5)` doesn't block anything useful: the value 5 is in the unimplemented low bits and reads back as 0.
- **Why:** BASEPRI takes the left-aligned byte (`5 << 4 = 0x50`).
- **Fix:** `__set_BASEPRI(5U << (8U - __NVIC_PRIO_BITS))`, or the lab's `Priority_Encode()`. (`NVIC_SetPriority()` takes the *level* and shifts for you.)

### 5. Signed and unsigned compares mixed up
- **Symptom:** `if (a < b)` is wrong for values with the top bit set.
- **Why:** the condition code follows the *type*: `LT` reads N and V, `LO` reads C. The same bits give opposite answers for `0x80000000` and `1`.
- **Diagnose:** the lesson's flag table: `CMP 0x80000000, 1` gives N = 0, C = 1, V = 1.
- **Fix:** use the right type (A0.1), and compile with `-Wsign-compare`.

### 6. Assuming a register survives a call
- **Symptom:** inline assembly that keeps a value in R1 across a `bl` loses it.
- **Why:** R0–R3 and R12 are caller-saved: any called function may overwrite them.
- **Fix:** keep values across calls in R4–R11, or declare the clobbers in the inline asm.

### 7. Setting the PSP or CONTROL and forgetting the barrier
- **Symptom:** the next instructions still use the old stack; a task starts on the wrong stack.
- **Why:** `msr CONTROL` isn't self-synchronizing; the stack choice changes only after an `ISB`.
- **Fix:** `__set_CONTROL()` (it includes the `ISB`), or add `__ISB()` after your own `MSR`.

### 8. Reading the Thumb bit from `MRS xPSR`
- **Symptom:** "my core isn't in Thumb state: T reads 0."
- **Why:** `MRS` returns zero for the EPSR bits (DUI 0553). The stacked xPSR (what a fault handler sees) has T = 1.
- **Fix:** read the Thumb bit from the *stacked* xPSR in a fault handler (A15.2), not from `MRS`.

### 9. A handler address without bit 0
- **Symptom:** `UsageFault` with `INVSTATE` as soon as an exception is taken, usually after hand-writing a vector table or a jump table.
- **Why:** a branch target with bit 0 clear selects the ARM state, which does not exist.
- **Fix:** let the linker create the vector entries from function names, or `| 1U` the address (A2.2).

### 10. Keeping interrupts off for too long
- **Symptom:** UART overruns, missed timer captures, jitter that grows with a feature that "only disables interrupts briefly".
- **Why:** PRIMASK blocks *everything* configurable. A 200 µs section blocks a 115,200-baud UART (87 µs per byte) for two bytes.
- **Fix:** keep sections to a few instructions, use BASEPRI to leave urgent interrupts running, and measure the longest section with the DWT counter (A3.5).

## Best practices & production tips

```callout production title="How professional firmware uses the core registers"
- **Critical sections save and restore.** One helper (`Critical_Enter()` returning the saved mask, `Critical_Exit(saved)`), used everywhere. Never a bare `__enable_irq()` in library code.
- **Prefer BASEPRI to PRIMASK on M3/M4/M7.** It leaves the most urgent interrupts running. Use `BASEPRI_MAX` for nesting.
- **Make priorities named constants.** `#define PRIO_MOTOR 1U`, `#define PRIO_UART 5U`, converted with `NVIC_SetPriority()`. Keep the table in one header and check it against the RTOS's maximum syscall priority with a `static_assert`.
- **Keep critical sections tiny and bounded.** No loops of unknown length, no calls into code you don't control, no `printf`. Measure the longest one.
- **Use the compiler's types to choose signed or unsigned.** The condition codes follow. A `-Wsign-compare -Wconversion` build catches most mistakes.
- **Don't write assembly that assumes the AAPCS from memory.** Use `__asm volatile` with proper clobbers, or write a whole function in a `.s` file that follows the register rules.
- **Read the stacked registers on a fault.** The stacked PC, LR and xPSR are the first thing to look at (A15.2). A minimal handler that captures them is worth having in every project.
- **Check `PRIMASK`/`BASEPRI` when debugging "dead" interrupts.** An interrupt that never fires is often masked by code that forgot to restore it.
```

## Cheat sheet

```callout tip title="A1.2 on one screen"
**Registers:** R0–R3 args/result/scratch · R4–R11 callee-saved · R12 scratch · SP = MSP or PSP · LR return address (`EXC_RETURN` in a handler) · PC (bit 0 = Thumb, always 1 for targets) · xPSR · PRIMASK · FAULTMASK · BASEPRI · CONTROL.

**AAPCS:** first 4 word arguments in R0–R3, rest on the stack · result in R0 (64-bit in R1:R0; hard-float `float` in S0) · save R4–R11 (+LR) before using them · SP 8-byte aligned at calls.

**xPSR:** N31 Z30 C29 V28 Q27 · T24 · GE[19:16] · IT [26:25],[15:10] · **ISR [8:0]** (0 thread, 2 NMI, 3 HardFault, 11 SVC, 14 PendSV, 15 SysTick, 16+n IRQn).

**Flags:** ADD: C = unsigned carry, V = signed overflow · SUB/CMP: **C = no borrow** (`a >= b`), V = signed overflow.
**Conditions:** unsigned `HS` C · `LO` !C · `HI` C&!Z · `LS` !C|Z · signed `GE` N=V · `LT` N≠V · `GT` !Z&N=V · `LE` Z|N≠V.

**Masks (4 priority bits):** priority byte = `level << 4`.
| Register | Blocks |
|---|---|
| PRIMASK = 1 | all configurable levels |
| FAULTMASK = 1 | all but NMI (cleared on exception return) |
| BASEPRI = b | bytes ≥ b (BASEPRI 0x50: levels 5..15 blocked, 0..4 run) |

**Critical section:** `saved = __get_PRIMASK(); __disable_irq(); … __set_PRIMASK(saved);` · with BASEPRI use `__set_BASEPRI_MAX()` and restore the saved value.

**CMSIS → asm:** `__disable_irq` `cpsid i` · `__set_BASEPRI` `msr BASEPRI` · `__set_CONTROL` `msr CONTROL` + `isb` · `__get_xPSR` `mrs PSR`.

**Exception entry stacks 8 words:** R0–R3, R12, LR, PC, xPSR (26 with FP context). R4–R11 are the software's job.
```
